# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Shizuku is a macOS Input Method Engine (IME) written entirely in Rust (no Swift). It converts romaji to kana, converts kana to kanji with a Rust port of azooKey's conversion engine, re-ranks full-sentence candidates with a small on-device language model (the judge), and learns the candidates you commit.

## Development Commands

Tasks are defined in `mise.toml`.

### Building and Packaging
- `mise run app` - Build the release binary and package `output/Shizuku.app` (copies `Info.plist`, `resources/` including `resources/judge/` if present, `dictionary/`, `LICENSE`, `NOTICE`, `THIRD_PARTY_LICENSES`)
- `mise run judge-model` - Download rinna/japanese-gpt2-xsmall (MIT, pinned revision) from Hugging Face and write `resources/judge/model_q8_0.gguf` + `tokenizer.json` with `tools/gen_judge_model.py` (uv script; set `HF_HUB_OFFLINE=1` to use only the local HF cache). The files are 41MB, gitignored and never committed. Run it before `mise run app`; without them the app still works on the engine's order and logs `judge: not configured` once
- `cargo build --release` - Build the Rust binary only (must stay free of warnings)
- `mise run install` / `mise run uninstall` - Copy to / remove from `~/Library/Input Methods`
- Distribution is a Developer ID-signed, notarized `.pkg` (no Homebrew cask): `scripts/stage-app.sh`, `scripts/sign-app.sh <identity|->`, `scripts/package-app.sh` (secondary zip), then `scripts/build-pkg.sh <installer identity|->` writes `dist/Shizuku-<version>.pkg` (current-user-home domain only, so no admin password). `-` leaves it unsigned for local checks (`pkgutil --payload-files`, `pkgutil --expand`); never run `installer` against your real `~/Library/Input Methods` to test. The pkg updates an existing bundle in place (`BundleOverwriteAction=update`), because the default whole-bundle swap leaves Shizuku unusable until it is removed and added again in Input Sources; its postinstall removes files the new version no longer ships, which would break the code signature seal. Deleting the bundle first drops it from Input Sources
- `mise run logs` - Stream the IME's NSLog output
- `mise run reset-memory` - Delete the learning data

### Testing
- `cargo test` and `cargo test --release` - Unit tests (composer, session, controller, keymap, kkc, ...)
- `mise run scenarios` - Replay `tools/scenarios.txt` headless; a line with an expectation that does not hold fails
- `mise run scenarios-learning` - Same for `tools/learning_scenarios.txt` with learning on (memory goes to a temp dir)
- `mise run simulate -- 'kyouha<space><enter>'` - Run a key sequence through the real key path without Cocoa (`SHIZUKU_SIM_LEARNING=1` to enable learning)
  - Besides keys, the sequence takes IMK-side event tokens (numbers are 1-based): `<pick:N>` (click a candidate), `<highlight:N>`, `<live>` / `<space-mode>`, `<commit-all>` (commitComposition). See the header of `src/simulate.rs`.
- `mise run wysiwyg` - Same files with `--check-preedit` (also valid for `--simulate`): after each key where something is underlined (pending romaji included), the same key prefix is replayed in a fresh simulator followed by a real Enter, and the text it commits must equal the underlined text (independent of `Composer::preedit` / `commit_preview`; learning must be off); a break fails the line as `WYSI` and names the keys. Rule: the underlined text is what Enter commits. A typed text that is a known English word (learned, `dev_words.txt` incl. 3-letter ones such as `git`, or a 4+ letter dictionary word; `/` before it allowed) shows and commits raw; otherwise a trailing consonant stays after the kana in both (`kyout` -> きょうt); no kana at all (`k`, `nk`, `kk`) shows and commits raw
- `mise run main-queue` - Post tasks from another thread with `platform::run_on_main_boxed` and check they run on the main thread, in order, with a panic in one not stopping the rest (no network)
- `mise run kkc-compare` - Compare the Rust engine against the Swift golden data in `tools/golden/` (top-1/3/9 must stay at 100%)
- `mise run judge-bench -- <testset.tsv>` - Judge accuracy and time over the real engine + judge path (`--judge-bench`; the argument is a TSV you supply, each line `reading<TAB>gold1|gold2`, optionally `<TAB>context` (the text committed just before; rows with it are also scored without it and the judge ms of the first key after a context change is reported separately); prints engine top-1 vs judged top-1 and judge ms). The test set is not committed, so you have to make your own TSV. Needs `resources/judge/` (or `SHIZUKU_JUDGE_DIR`)
- `SHIZUKU_SIM_TIMING=1` with `--simulate*` prints per-key and judge time percentiles and RSS (set `SHIZUKU_JUDGE_DIR` to make the simulator load the judge; it is off there by default so the oracles stay deterministic). The key-event trace also records `keyTime` and `judge` (milliseconds only)
- Other dev tools: `--kkc-check`, `--kkc-convert <reading>`, `--kkc-bench <reading>` (run `./target/release/shizuku <flag>`)
- Manual testing of the IME itself needs the app installed in `~/Library/Input Methods` and added in System Settings > Keyboard > Input Sources.

### Dictionary location
Order: `SHIZUKU_DICTIONARY` (an invalid value is an error, no silent fallback) -> `<exe>/../Resources/dictionary` (app bundle) -> the repo's `dictionary/` **only in debug builds and tests**. Release binaries never fall back to the repo, so a missing bundle copy shows up in dev installs. The mise tasks above set `SHIZUKU_DICTIONARY` for you; when running `./target/release/shizuku --kkc-*` / `--simulate*` by hand, set it to `$PWD/dictionary`.

If the dictionary cannot be opened, the failure is logged once (NSLog), reopening is retried at most every 5 minutes, and conversion degrades to hiragana / katakana / raw candidates.

### Dependencies
Versions published less than 7 days ago must not be used (like pnpm's `minimumReleaseAge`). `mise run release-age` (`scripts/check-release-age.sh`) checks every crates.io package in `Cargo.lock` against the crates.io API (fails closed; `MIN_AGE_DAYS` overrides; results cached in `target/release-age-cache.tsv`). Emergency exceptions: a line `name version # reason` in `tools/release-age-allow.txt`. uv uses `exclude-newer = "7 days"` in `tools/gen_judge_model.py` (re-run `uv lock --script tools/gen_judge_model.py` after changing dependencies), and `mise.toml` sets `minimum_release_age = "7d"`. CI runs the check in `ci.yml` only, not in `release.yml`, so a dependency aging past 7 days never blocks rebuilding an already-reviewed release.

## Architecture

- `src/main.rs` - Entry point; dispatches dev-tool flags, otherwise starts the IME (`imk::register_controller`, `imk::run`)
- `src/platform.rs` - Cocoa / InputMethodKit / libdispatch glue via `objc2` (NSLog, main-queue dispatch wrapped in `catch_unwind`, candidate panel, defaults, secure-input check). Keep new `unsafe` here (it also holds the Accelerate `cblas_sgemm` (`sgemm_abt`) and NEON `q8_dot_rows` code the judge calls, plus the QoS / App Nap calls); `src/imk_client.rs` (host app text client) and the Objective-C class declaration in `src/imk.rs` are the only other places with it. `src/judge.rs` is `#![forbid(unsafe_code)]`. All other modules are `#![forbid(unsafe_code)]` or have none.
- `src/imk.rs` - `ShizukuInputController` (IMKInputController subclass). Turns IMK callbacks into `Session` calls and executes the returned `Effect`s. Holds the per-controller state.
- `src/session.rs` - One key's worth of decisions (delegates to the composer); returns `Effect`s. Headless, drives `simulate.rs` and the tests.
- `src/keymap.rs`, `src/romaji_converter.rs`, `src/translit.rs`, `src/symbols.rs`, `src/loanword.rs`, `src/emoji.rs` - Key classification, romaji -> kana, script conversion (F6-F10), symbol variants, katakana-word -> English candidates, reading -> emoji candidates (data in `resources/*.tsv`, generated by `tools/gen_*.py`)
- `src/composer.rs` - Composition phases (Composing / Converting / Dangling / ...), the candidate list, and the only owner of the pending romaji (`preedit()` decides the underlined text, `commit_preview()` what Enter commits). Falls back to hiragana + katakana candidates when the engine returns nothing. A pending romaji of exactly `n` in Kana editing is shown as ん (`pending_kana`: the reading, the live conversion and Enter all include it, the next key still replaces it as in `mina` -> みな, and Backspace reconverts the reading without it) unless Enter's flush would turn the composition into English, and `Controller::commit_preview` (the WYSIWYG oracle) covers that case.
- `src/kkc/` - azooKey-compatible kana-kanji engine: `dict` / `louds` (dictionary files), `lattice` (N-best Viterbi), `wise` (dynamic entries), `result` (candidate assembly), `learning` (committed candidates -> `learning.tsv`; in-memory update is immediate, a background writer coalesces file writes), `compare` / `check` (dev tools). `RustEngine` is the `CandidateEngine` used by the IME. `RustEngine::convert` returns the first 9 engine candidates plus variants (judge-reranked), then a tail from `main[9..]` of up to `MAX_SHOWN` (30) engine candidates in total: only whole-reading candidates (the words' rubies concatenate to the reading), deduped, with ASCII-only texts skipped (the composer adds loanwords itself). When the composer adds an emoji or loanword and an engine copy of the same text sits later in the list, it removes that copy and inserts at its own slot (`Composer::claim_slot`; `EngineRank` lives on each candidate, so learning indices do not shift), appended in engine order and never judged. `last` has the same order, so select / learning work for them. Known limit, not fixed here: a FirstClause candidate inside the first 9 still drops the rest of the reading on commit. Digit keys pick candidates 1-9 only while the panel cannot have scrolled (`Composer::digits_pick`): once the cursor reaches #10 or later the scrolling panel's row labels are unknown, so digits are swallowed until the cursor is back on #1. With ~30 candidates the raw reading is last, so wrapping around with Shift+Space takes more presses.
- `src/judge.rs` - On-device judge: rinna/japanese-gpt2-xsmall (GPT-2, 6 layers) kept as q8_0 blocks. `RustEngine::convert` scores every `Source::Full` candidate by log-likelihood and reorders them together with the engine score (live and Space modes). Small batches use an integer dot product (NEON sdot, `platform::q8_dot_rows`), larger ones dequantize per layer into Accelerate sgemm; a shared-prefix KV cache spans keystrokes; the model loads on a background thread at startup (`preload`) and workers run at QOS_USER_INTERACTIVE, and App Nap is held off only while a composition is in progress (`Environment::set_composing` -> `platform::Activity`, begun when the session leaves Empty and ended when it returns to Empty). After the load, the long-lived buffers (q8 weights and scales, f32 tensors, dequant scratch; about 43MB, not the KV cache) are `mlock`ed via `platform::lock_memory` so the OS cannot compress them while the IME idles between compositions (a failure is logged once and the judge runs unlocked; trace `judge-locked mb=N ok=1|0`). Keys typed before the load finishes just use the engine order. No network, and the model files are looked up under `Resources/judge` (`SHIZUKU_JUDGE_DIR` overrides). Every tensor shape is checked at load (a mismatch means no judge, logged once, never a per-key panic); a panic while scoring drops the KV cache and that key keeps the engine order. Measured on an M-series Mac (release build): peak RSS (`/usr/bin/time -l ./target/release/shizuku --simulate '<252 romaji chars><enter>'`, maximum resident set size, 3 runs each) is about 41MB without the judge and about 116MB with it (`SHIZUKU_JUDGE_DIR` set; peak memory footprint 33MB vs 107MB). The load never holds the whole model file: `src/gguf.rs` streams each tensor in 1MB reads straight into the judge's q8 / f32 buffers. Judge time over 318 `--judge-bench` decisions: median 7.7ms, p95 9.3ms, max 19.5ms
- `src/gguf.rs` - Minimal GGUF reader for the judge model (`#![forbid(unsafe_code)]`): opening it parses only the header (v2 / v3), metadata (only `general.alignment` is used) and tensor infos through a small buffered read; `Gguf::read` then seeks to one tensor and hands its bytes to a callback in chunks cut at element / block boundaries (`File` + `seek` / `read_exact`, no mmap), so the whole file is never in memory at once. Only F32 and Q8_0 tensors (what `tools/gen_judge_model.py` writes); anything malformed or unsupported is a fixed-message `Err`, never a panic.
- `src/tokenizer.rs` - The judge's tokenizer: reads `tokenizer.json` (SentencePiece Unigram with a Precompiled charsmap and Metaspace) and returns the same ids as the `tokenizers` crate 0.21 `encode(text, false)` did. The file's pipeline is checked at load (anything else means no judge). `tools/tokenizer_ids.jsonl` holds (input, ids) pairs captured from that crate; the test that compares against it skips when `resources/judge/tokenizer.json` is absent.
- `src/context.rs` - Per-app (bundle id) memory of the text the user typed through Shizuku, in process memory only (10 apps, last 100 chars each, plus a 32-vote English/Japanese window per app (one vote per insert), forgotten after 12 hours of uptime without input (sleep not counted); host app text is never read; not recorded when learning is not allowed). Enter is recorded as a `\n` break (every Enter is kept so Backspace stays in step); Enter, cursor keys, Cmd/Ctrl/Option shortcuts and commitComposition do not clear it, only a pass-through Backspace pops one char. `Controller` records it and passes it per key to `Session::set_context`, which hands the whole multi-line text to the judge (the candidate is scored after the context, last 32 tokens; the tokenizer turns `\n` into a space) and, when the current line (after the last `\n`) ends in ASCII, makes `! ? ( ) { } . , : ;` at the start of a composition go in half-width. `ContextStore::record` also counts one vote per insert (any kana/kanji/katakana = Japanese, else any ASCII letter = English, digits/symbols/spaces/newlines = no vote; counts only, never text); `is_english_app` is true with ≥12 votes and ≥75% English. `Controller` passes that boolean per key (`Session::set_context(context, english_app)`) and the judge's English-word check (`RustEngine::prefers_text`, MARGIN 4.0: English wins over a kana headword) then also asks at a line start (blank current line), never mid-Japanese-line; the veto (`rejects_english`, 2.0) is unchanged, except that a word in `resources/dev_words.txt` is never vetoed (`Composer::judge_word`; so `api` stays English, and such a word must not be everyday Japanese romaji such as `node` = ので). Learned and loanword-table words keep the veto. A `-` right after such a whole-word English composition continues as a long vowel (`api-ru` -> アピール) only when a dictionary headword starts with its reading + ー (`CandidateEngine::has_reading_prefix`); otherwise it commits the word and inserts `-`. Mid-Japanese (`kyouhaapi`) is not covered. The trace carries only `english_app=0|1`. Never logged.
- `src/outbound.rs` - Whether learning (and context memory) is allowed: not under secure input and not in password managers (`PASSWORD_MANAGERS`); and whether keys pass straight through as direct input, which happens under secure input only. Password manager apps compose Japanese normally but learn nothing and record no context.
- `src/trace.rs` - Optional key-event trace (`defaults write dev.n-seiji.inputmethod.Shizuku ShizukuTrace -bool true`); never records typed text.

### Rules worth remembering
- Never log or print user text (readings, candidates, surrounding text).
- Learning data lives in `~/Library/Application Support/Shizuku/rust-learning/learning.tsv` (`SHIZUKU_MEMORY_DIR` to override, `SHIZUKU_DISABLE_LEARNING=1` to turn off). Concurrent IME processes are last-writer-wins. Words committed as English (Dangling) go to `english.txt` in the same directory (`src/english_memory.rs`). Picking the raw-typed English word (`done`, `the`: 3+ lowercase letters, a dictionary word, not Mixed / Judged) from the candidate list also learns it (`Committed.picked`; not on commitComposition). A learned word whose kana is a headword (done -> どね) then types as English unless the judge vetoes (no judge loaded = always English), and `english_split` still refuses it as a head when its kana is a Japanese word (`donewo`, `madeni`). Space on such a word commits `done ` at once; Shift+Space converts. Known flicker: a learned word that begins a longer Japanese word (kite -> kitekudasai) shows English for one key. F10 commits are not learned.
- Live conversion is one process-wide setting (`ShizukuLiveConversionEnabled`, default off = Space); every controller follows it on its next key / menu open.

### Dependencies
- `objc2`, `objc2-foundation` - Objective-C runtime bindings
- `regex`, `unicode-segmentation`, `unicode-normalization`, `serde_json`
- `rayon` - the on-device judge. The GGUF model file is read by the in-tree `src/gguf.rs` and the tokenizer is the in-tree `src/tokenizer.rs` (no crates), and the matmuls call Accelerate directly from `platform.rs`
